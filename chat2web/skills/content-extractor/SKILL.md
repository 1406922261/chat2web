# 关键信息提取

## 目标

从聊天中抽取“可以放到网页上”的素材，并保证每条素材都有出处、没有重复、没有编造。

## 提取维度

| 维度 | 说明 | 示例 |
| --- | --- | --- |
| goal | 用户想达成的结果 | “一个月训练四次/周” |
| preference | 明确表达的喜好 | “喜欢清淡口味” |
| constraint | 限制与禁忌 | “预算 3000 以内” |
| time | 时间、周期、频次 | “玩三天”“每周四次” |
| number | 数量、价格、组数 | “每天 40 分钟” |
| place | 地点 | “西湖”“灵隐寺” |
| person | 人物与角色 | “和同事一起”“负责人小王” |
| item | 具体条目 | “龙井虾仁”“深蹲” |
| decision | 已确定的结论 | “最终选 A 方案” |

## 处理规则

1. **保留原意**：只做轻微压缩，不改变语义；数字与单位原样保留。
2. **去重**：相同含义只保留信息量最大的一条（“每周四次”优先于“经常练”）。
3. **归并**：把零散短句合并成可读要点，但不要把两条不同事实硬拼。
4. **实体优先**：地点、菜品、书名、动作名、项目名单独列出，便于页面生成卡片。
5. **缺失标注**：网页需要但聊天没说的，写入 missing，例如“未提及交通方式”。
6. **禁止推断事实**：不能根据常识补充价格、地址、评分、配料等聊天中不存在的信息。

## 输出检查

- 每条信息能对应到聊天中的一句话。
- 不存在两个重复要点。
- 缺失信息不会被包装成肯定句。
- 实体可以直接用于导航、标签、卡片标题。
