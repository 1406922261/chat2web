# 网页结构规划

## 目标

先判断“这是一个什么网站”，再决定“需要哪些页面、每页放什么”，最后才进入开发。

## 判断顺序

1. **网站类型**：由内容决定，例如旅游攻略、健身计划、学习路线、读书笔记、项目介绍、活动策划、产品发布页、成长记录、会议纪要、美食清单。允许创造新类型。
2. **核心任务**：访客打开首页后最该做什么？了解全貌、查看安排、跟踪进度、阅读笔记，还是联系/行动？
3. **页面拆分**：每个页面承载一个独立信息维度，避免把全部内容堆在首页。
   - 内容量少 → 1-2 页；内容量多 → 3-6 页。
   - 常见维度：概览、计划/安排、清单/推荐、进度/数据、预算/限制、总结/行动。
4. **模块顺序**：首页先给结论，再给亮点，再给入口；详情页按时间或重要性排序。
5. **交互需求**：需要筛选、标签切换、进度条、折叠、搜索时，明确写在 interactions 中。

## 不同主题的结构差异（示例，不是模板）

- **旅游**：概览 → 行程 → 景点 → 美食 → 预算与贴士。
- **健身**：目标 → 每周安排 → 动作库 → 进度记录。
- **学习**：目标 → 阶段路线 → 每日计划 → 进度追踪。
- **读书**：书籍与作者 → 笔记要点 → 摘录 → 行动。
- **项目**：背景 → 功能模块 → 开发计划 → 风险与待办。
- **会议**：概况 → 讨论要点 → 决议 → 待办分工。

这些只是思路示例，实际页面必须根据聊天内容增删。

## 内容映射

- 每个模块的 items 必须来自分析结果中的事实/实体/偏好。
- 缺少信息时写“待补充：具体缺什么”，不要为了页面完整而编造。
- 同一事实不要重复出现在多个页面；如需引用，换一种信息角度。

## 输出检查

- 网站类型与聊天主题匹配。
- 页面之间有清晰分工，没有两个页面内容雷同。
- 每页至少 2 个模块，每个模块有实质内容。
- 视觉风格与主题一致（清新/专业/活力/温润…）。
