# 聊天内容分析

## 目标

把一段可能杂乱的多轮聊天记录，变成可执行的网页生成输入。你不是复述原文，而是理解后重组。

## 分析步骤

1. **区分说话人**：识别“用户 / 我 / AI / 助手”等前缀。用户的诉求优先于 AI 的补充说明。
2. **找出主线**：聊天可能包含多个话题，选择信息量最大、用户投入最多的一条作为主主题。
3. **识别意图**：用户想要攻略、计划、记录、介绍、复盘，还是整理？意图决定网页类型。
4. **保持上下文**：后出现的修正（“其实我想改成…”“不去这里了”）覆盖先前的说法。
5. **标注不确定**：聊天中没说清楚的，列入待补充，禁止脑补。

## 输出结构

```
topic       简短主题（如：杭州三日游 / 一个月增肌计划）
category    内容类别（旅游攻略 / 健身计划 / 学习计划 / 读书笔记 / 项目介绍 / 活动策划 / 产品介绍 / 个人成长 / 会议整理 / 美食推荐 / …）
summary     120 字内摘要：目标 + 关键内容 + 结论
key_facts   [{kind, key, value}]，kind 动态决定，不预设领域字段
sections    [{title, points}]，2-5 组自然分组
preferences 用户明确表达的偏好
entities    地点/人物/书名/菜品/项目名等实体
missing     缺失但网页需要的信息
```

## 质量检查

- 每个 key_fact 都能在原文找到依据。
- 不同聊天主题产生不同字段，不能把“目的地 / 美食”等旅游字段写死。
- 摘要能让没看过聊天的人理解需求。
- 待补充项具体，例如“未提及预算范围”，而不是“信息不足”。

## 反例

- 直接复制用户原话当摘要。
- 把 AI 的礼貌用语当成用户需求。
- 为了让页面丰富而虚构数字、地点或结论。
